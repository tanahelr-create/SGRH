Ajoute également une gestion complète et réaliste de la CARRIÈRE du personnel universitaire malgache.

Le système doit distinguer au minimum les deux grandes familles :

* Enseignants-chercheurs / chercheurs ;
* PATS / personnels administratifs, techniques et de service.

Il faut également distinguer, lorsque c'est pertinent, les fonctionnaires et les agents contractuels, car leurs parcours administratifs et leurs régimes ne sont pas identiques.

La carrière ne doit pas être représentée uniquement par une situation actuelle. Le système doit conserver un HISTORIQUE CHRONOLOGIQUE des événements de carrière.

Prévoir notamment les événements suivants lorsque ceux-ci sont applicables au personnel :

* recrutement ;
* stage ;
* titularisation ;
* prolongation de stage ;
* avancement d'échelon ;
* avancement de grade ou de classe ;
* reclassement ;
* changement de fonction ;
* changement d'affectation ;
* changement de service ou d'établissement ;
* mise à disposition ;
* détachement ;
* disponibilité ou autre position administrative applicable ;
* formation et obtention de diplômes ;
* changement de qualification ;
* avenant au contrat ;
* renouvellement de contrat ;
* suspension ou événement disciplinaire lorsqu'il doit être géré par le système ;
* retraite ;
* fin de contrat ;
* cessation définitive de fonctions ;
* réintégration lorsqu'elle est applicable.

Pour chaque événement de carrière, conserver autant que possible :

* type d'événement ;
* date de l'événement ;
* date d'effet ;
* ancienne situation ;
* nouvelle situation ;
* corps ;
* grade ;
* classe ;
* échelon ;
* indice ;
* fonction ;
* affectation ;
* motif ;
* référence de la décision ;
* autorité ayant pris la décision ;
* observations ;
* document justificatif ;
* utilisateur ayant enregistré/modifié l'information ;
* date de création/modification de l'enregistrement.

Pour les enseignants-chercheurs, prévoir les informations spécifiques nécessaires à leur parcours académique et professionnel, notamment les grades, diplômes, qualifications et événements propres à leur carrière.

Pour les PATS, prévoir les informations administratives correspondant à leur parcours.

Pour les agents contractuels, prévoir notamment la gestion des contrats, avenants, renouvellements et fins de contrat.

IMPORTANT :
Ne code pas en dur des règles juridiques comme une durée ou un âge unique lorsqu'elles peuvent dépendre du corps, du statut, du régime ou d'un texte applicable. Le système doit surtout permettre d'enregistrer la décision administrative réelle, sa date d'effet, sa référence et son document justificatif.

La carrière doit être affichée sous forme de chronologie afin qu'un administrateur puisse comprendre l'évolution complète du personnel depuis son recrutement jusqu'à sa situation actuelle ou sa sortie de service.

Cette fonctionnalité doit également être intégrée au système d'audit : toute modification ou suppression d'un événement de carrière doit laisser une trace consultable par le SUPERADMIN, avec les valeurs AVANT/APRÈS lorsque cela est possible.

Ne recrée pas la base de données et ne détruis aucune donnée existante. Analyse d'abord le modèle actuel de carrière et propose les migrations nécessaires avant de les appliquer.
